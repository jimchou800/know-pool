# 工程与验证基线

当前执行以根 `AGENTS.md` 最新用户要求为准：生产构建与真实运行优先，工作流不执行契约工具测试、评测工具单元测试、前后端单元测试与覆盖率，也不生成严格契约报告。下文完整验证基线保留供以后显式恢复使用，不作为本轮运行验收的阻塞项。

## 选型和目录

根 Maven 工程管理公共版本与 Java/Maven 版本门禁，聚合 `front/`、`server/`、`verification/`。前端模块执行前端检查与构建；后端模块执行 Java 检查、测试、资源装配与打包；验证模块依赖前后端产物，在最后执行工具自检、真实浏览器联调和契约报告，避免根父工程先于子模块运行集成验证。目标版本为 Java 21、Spring Boot 4.1.x、Spring AI 2.0.2、Maven 3.9.x；精确补丁、SQLite 驱动、迁移工具与整套依赖须验证锁定。前端为 Vue 3、Vite、Pinia、Vue Router 4、Axios、JavaScript（以 ECMAScript 6 为语法基础）与原生 CSS。pnpm 镜像为 `https://registry.npmmirror.com/`，提交锁文件，冻结安装。

后端按业务包隔离，包内区分接口、业务、数据访问，避免循环依赖及跨业务直接访问数据访问层；不为每类机械建立接口。前端按功能组织，实际复用后提取公共内容。仅创建任务需要的目录。核心运行与数据约束见现行架构及完整规格。

## 门禁

| 范围 | 必须执行的验证 |
| --- | --- |
| 后端 | Spotless 与 Palantir Java Format、SpotBugs、JUnit 5、ArchUnit、编译和构建 |
| 前端 | ESLint 与 Vue 规则、Prettier、Stylelint、Vitest、Vue Test Utils、生产构建 |
| 覆盖率 | 前后端分别计算，行覆盖率及分支覆盖率各至少 80%；生成代码与纯配置可明确排除并公开范围 |
| 契约 | 静态校验、差异与双向确认、提供方及消费方自动验证、自动报告；全部正式操作及约束 100% 对齐 |
| 集成 | 固定资料与模型替身下的成功、非法输入、失败、取消、版本及删除传播场景 |
| 界面 | 实际浏览器检查交互、状态、键盘焦点和中文文案，截图记录；不是只检查页面能加载 |

所有验证在根工作区的 `integration` 分支执行，启动前确认分支。先完成实现、收敛文档，再按相关任务批次统一验证和修复；多票可共享一次流程的证据，优先使用交叉验证和包含式验证，不逐票或逐小改动重复运行。

根 `mvn verify` 已覆盖的检查不在其前后无理由重跑。诊断失败时可定向运行受影响模块，修复收敛后在同一集成快照执行完整门禁；只有相关输入变化、失败修复或证据缺口才补跑。保留命令、实际退出结果、快照和覆盖范围，不能用旧快照证据宣称新改动通过。当前进展查根 README 及任务正文。

根门禁包含源码构建的真实同源联调；正式运行时包的装配及Chrome、Edge回归只补充源码门禁不能证明的发行环境能力，见[发行说明](../release.md)。接口报告与两阶段独立验收仅按[接口规范](api/README.md)维护；门槛不因合并验证降低。

新增分支、循环、解析、安全及恢复逻辑须有最小有效测试；缺陷测试覆盖原失败场景。覆盖率达标不代替行为验证，自动契约覆盖与代码覆盖分别计算。关键例子包括重复上传、同名并发、取消迟到响应、版本读取保护、错误知识库过滤、引用校验失败、凭据泄漏、SQLite/Qdrant 部分失败以及迁移中断。

## 构建、发行与效果

frontend-maven-plugin 固定 Node.js 和 pnpm 并接入根 Maven；前端可独立开发。开发 Vite 代理，发行 Spring Boot 同源提供静态资源及接口。Windows x64、主流 Chrome/Edge 为验收范围；发行压缩包包含 Java 运行时和启动脚本，Node.js 仅构建使用，Qdrant 独立部署。不得携带个人资料、密钥、数据库或开发运行数据。

普通测试及持续集成使用固定资料、模拟模型，不依赖真实凭据或收费接口。中文固定评测集单独测召回、排序、子问题覆盖、准确性、忠实度、引用定位和支持性、耗时及费用；真实模型评测单独获得授权。先测向量基线，依效果决定是否引入混合检索及重排。

上限、阈值、预算、队列、超时和工具补丁需通过代表性资料与目标环境测量确定；不要把占位值或模拟模型结果当作产品质量验收。
