# 多代理协作与派活

## 角色和派发

总协调 Codex 负责需求映射、垂直切片、前置验收、接口变更协调、共享文件、集成及最终验收。前端代理读取 `.codex/agents/fornt-agent.md`，负责前端领域；后端代理读取 `.codex/agents/backend.md`，负责后端领域。文件只是角色说明，不会自行注册、运行或改变工具权限；启动工具代理时必须在任务中传入角色文件路径。

纯前端问题交前端代理，纯后端问题交后端代理；涉及请求、响应、事件、上传、下载或安全协议的工作必须两方参与。一个业务任务是贯穿契约、数据、后端、前端与测试的端到端切片；领域工作包可并行，但任一方未完成不能将切片视为完成。只读审阅不能冒充正式接口确认。

## 执行顺序

1. 总协调确认任务已获批准且所有阻塞任务完成验收，记录前后端负责人、修改范围和共享文件写入者。无阻塞任务按编号优先领取；不要让两个代理修改同一文件。
2. 双方先阅读规格及唯一接口契约，列出本切片操作和约束；契约缺失时总协调直接派发契约设计工作，指定单写入者，双方自行提出技术方案、互审并完成同一摘要的独立确认，再派发实现。路径、字段编码、错误结构等技术选择由双方协商，总协调依据规格和证据解决技术分歧；只有业务含义不确定或需要改变已确认规则时向用户核实。用户需求改变时同步任务与契约，不能用代理共识替代产品决策。
3. 总协调发送工作包：任务编号、交付行为、已确认契约摘要和操作范围、允许编辑范围、依赖、测试、报告位置及对方代理。后端提供可校验响应与失败样例，前端提供真实请求与消费证据。
4. 两方各自自检，再交叉审阅请求/响应和自动契约报告，各自留下确认记录。代理意见冲突由总协调核对规格及证据；产品未决事项向用户核实。
5. 总协调在同一实现快照集成运行根验证和端到端场景，核验每个验收项、契约报告与两方确认。全部通过后记录执行结果；缺项保持未完成，不以部分领域成功关闭任务。

任务正文至少包含：用户可见行为、阻塞任务、验收条件、契约范围、前后端工作包与证据要求。契约、根构建、锁文件、数据迁移及共享规范采用单写入者，另一方只审阅并提出修改。

## 独立确认与失败处理

双方确认必须来自两个实际参与的领域代理，记录角色、契约摘要、实现快照、报告摘要、结论和证据。总协调不得代签，代理不得替另一角色确认；代理不可用时保留待确认状态，不伪造通过。

契约变动后两方确认均失效；实现变动后相关校验和报告验收失效。重新生成报告并重审，不复用旧 100% 结论。测试失败先修复，工具或网络阻断据实记录，保持任务未验收。

除用户明确授权的实现与测试外，不自动调用收费模型或发送他人消息。当前协作文件建立不等于项目已具备自动派发运行时、持续集成或契约校验器。
