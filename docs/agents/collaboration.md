# 多代理协作与派活

## 职责与单写入边界

总协调负责按依赖和编号推进垂直切片、共享文件、集成及验收；前端加载 `.codex/agents/fornt-agent.md` 并负责 `front/`，后端加载 `.codex/agents/backend.md` 并负责 `server/`。角色文件是派活说明，不代表工具已注册或启动代理。跨域切片由双方共同完成，不能交付两个未联通的半成品。

派活记录在原技术任务：用户可见行为、前后端负责人、依赖、允许编辑范围、唯一契约操作和摘要、必要测试及交付位置。契约、根构建、锁文件、跨域规范和状态由指定写入者维护；领域代理仅写获分配目录和本人独立签认，避免共享文件与暂存区相互覆盖。

## 执行与集成

1. 先读根代理约定和任务，确认前置实现已集成；按依赖顺序、同一前沿编号优先领取。实现状态与验收状态分开，具体状态见[任务跟踪](issue-tracker.md)。
2. 双方读取唯一接口契约。缺项时先承担设计工作，自行协商技术选择、指定契约写入者并独立审阅相同字节；只有业务含义不确定或要改变已确认规则时交用户裁定。接口流程只在[接口规范](api/README.md)维护。
3. 同票前后端可并行编写业务及必要测试；按根代理约定先完成实现，标记“已实现，待统一验证”。实现齐备及时合入 `integration`，核对无独有内容后清理任务分支、工作树并结束对应代理。
4. 先收敛文档，再按[工程规范](engineering.md)合并相关任务统一验证和修复。所有检查在根工作区 `integration` 执行；复用一次检查覆盖的多票证据，失败或相关输入变化才补跑受影响范围。
5. 同一实现快照的提供方、消费方、浏览器及自动报告齐备后，两领域分别审阅；总协调核对实际证据及全部验收条件，再标记已完成。代码提交或单方检查不能代替端到端验收。

## 独立确认与交接

设计签认与运行验收分开。确认须来自实际参与的两个领域代理，不得替对方签字；契约变化使旧设计确认失效，实现变化使相关运行证据失效。详细摘要和报告规则以接口规范为准，不在交接文件另立门禁。

交接只保留当前目标、已提交内容、关键决策、剩余工作、未验证项和下一步；及时压缩上下文。已采纳信息归入对应规格、任务或实施记录后清除临时交接，避免继续维护第二份进度。工具或代理不可用据实记录，保留待确认状态，不伪造完成。

真实模型和外部发布按根代理约定单独授权，普通持续集成只使用固定资料与替身。
