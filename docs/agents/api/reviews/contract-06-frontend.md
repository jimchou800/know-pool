## 初审拒绝项及最终复核

`CredentialState.description` 规定保留掩码替换一律返回400 `INVALID_REQUEST`，字段为 `/credential/value`。但 `updateEmbeddingVersionCredential` 的请求体直接引用 `CredentialChange`，其实际请求为根级 `action` 和 `value`，没有 `credential` 包装。`FieldError.field` 正式定义为“JSON 指针或参数名”，因此该操作的保留值错误指针应为 `/value`，当前描述指向不存在的字段，无法按实际负载定位输入及错误焦点。

最终草案已最小修正：共享描述明确普通模型及向量配置保存使用 `/credential/value`，指定历史版本凭据操作使用 `/value`；历史操作描述也独立注明根级请求和相同指针。不修改操作请求形状，不增加包装字段或新错误结构。跨源 `keep` 的 `/credential/action` 正确，因为涉及地址变化的三个保存请求均包含该包装，历史独立凭据操作不涉及地址变化。该拒绝项已关闭。
