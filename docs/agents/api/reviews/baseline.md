## 已执行验证

机器证据：[设计静态报告](../../../../.scratch/technical-design/contract-design-validation/static-report.json)。执行脚本：[validate.py](../../../../.scratch/technical-design/contract-design-validation/validate.py)。该脚本仅用于本轮设计检查，不是后续业务接口自动报告生成器。

- 使用 `openapi-spec-validator 0.7.2` 执行标准 OpenAPI 3.1 校验，通过。
- 使用 `jsonschema 4.23.0`、`referencing 0.35.1` 检查全部结构的模式合法性及 7 个契约内置样例，通过。
- 996 处内部引用均可解析，操作标识唯一、路径参数完整、会话安全、写请求保护及事件结构检查通过。
- 27 个正反边界样例通过：合法与非法文件名、末尾换行和控制字符、问题空白、空范围、重复范围、非法标识、未知字段、凭据三态及自定义元数据保护。
- 检查脚本以重复操作和缺失引用两个故障副本进行反向自检，均能拒绝。
- 独立范围代理核对规格与任务，反馈的问题经双方修复后无剩余业务覆盖阻断；评测和发行复用既有操作，不额外新增评测管理产品。

校验工具安装在已忽略的 `.runtime/contract-tools/`，未加入应用依赖。安装及读取工具目录受到沙箱限制时已按环境要求提权执行；最终工具执行成功。复跑时在仓库根目录执行 `python .scratch/technical-design/contract-design-validation/validate.py`，需能读取上述工具依赖；具体工具版本记录在机器报告。

## 开发派发规则

总协调按 `.codex/agents/fornt-agent.md` 与 `.codex/agents/backend.md` 派发领域工作，按原有依赖先执行 01。24 票仍处于实现未开始，契约设计完成不解除工程任务间的阻塞，也不把 01 标记为完成。

实现工作包记录任务操作标识、本契约摘要、共享文件单写入者、领域边界、测试与报告位置。14 先实现普通检索必需的最小实例创建链路，15 复用该操作并补完整实例交互，不引入第二种普通检索接口。

双方自行解决技术选择并交叉审阅；业务含义不确定或需要改变已确认规则时才向用户核实。契约变动按接口协作规范重新双审。接口开发完成后，自动产生绑定契约与实现快照的机器和中文报告，两方分别验收，再由总协调核验端到端证据。

## 尚未验证

本轮没有实现正式业务接口，没有执行业务构建、运行期提供方/消费方联调、竞态与恢复测试、真实模型调用或性能效果评测。设计样例通过不能证明实际实现对齐；实现对齐率目前不计算，不报告百分之百。根 `mvn verify`、持续集成与实现契约报告生成器仍由工程切片交付。
