# 本地任务跟踪

## 文件组织

- 每个功能使用 `.scratch/<功能标识>/`。
- 需求规格保存为 `spec.md`。
- 每个实现任务单独保存为 `issues/<两位编号>-<任务标识>.md`，从 `01` 开始。
- 文件顶部使用 `Status:` 记录状态，取值见 `triage-labels.md`。
- 讨论记录追加到文件末尾的“讨论记录”章节。

## 技能操作

“发布任务”表示创建对应的本地文件；“获取任务”表示读取指定文件。编号不唯一时，先确定所属功能。

## 探索任务

- 探索地图保存为 `.scratch/<探索标识>/map.md`，包含笔记、已定决策和待解问题。
- 子任务保存为 `issues/<两位编号>-<任务标识>.md`。
- `Type:` 使用 `research`、`prototype`、`grilling` 或 `task`。
- `Blocked by:` 列出前置任务编号；全部为 `resolved` 后才能开始。
- 优先选择编号最小、尚未解决、未被领取且无阻塞的任务。
- 开始前将 `Status:` 设为 `claimed` 并保存。
- 完成后追加“解答”章节，将状态改为 `resolved`，并在地图中补充结论及链接。

探索中的 `claimed`、`resolved` 仅用于探索任务的执行状态；普通任务使用五种分流状态。
