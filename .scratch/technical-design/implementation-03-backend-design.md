## 契约最小修补建议

最新预览和下载描述已写副本清理返回410，但两个操作的响应表没有410。建议补两个操作的共享410响应，错误码沿用现有 `CONTENT_UNAVAILABLE`，不新增业务操作；前端显示原副本当前不可用，不用最新其他正文代替。

- 文件标识不存在：404 `NOT_FOUND`。
- 元数据明确记录当前版本 `originalAvailable=false`：410 `CONTENT_UNAVAILABLE`。不因此主动清理最新副本，历史版本继续使用自身版本入口。
- 元数据仍标记可用、实际文件意外丢失或读取失败：500统一脱敏错误，避免用正常410状态掩盖损坏或磁盘故障；发现状态如何持久更新另按恢复切片处理。

上传请求资源校验和文本编码边界应写入同一契约说明或扩展约束，生成器保留其约束标识，前后端在同一摘要上确认。不得只在隐藏配置或本设计里定义接口新限制。

## 上传资源与内容规则提案

前后端直接协商的工程初值：单份原文件 `10 MiB`，整个 multipart 请求 `100 MiB`，总文件数沿用契约 `1000`；总大小包含封装开销，参数标识使用英文。数字是待实测的工程边界，不是性能完成声明。

2026-11-13本机仅做了固定ASCII文本流的Python数量级预检：重复 `fixed text fixture\n` 生成10485760字节，按65536字节块增量UTF-8解码与SHA-256，摘要 `754835be1c496be454a799dc89a30f44968249dfe07b7f43480b377fdfdd3146`，一次测量7.01毫秒，`tracemalloc`记录增量受追踪峰值66053字节。该脚本没有HTTP、磁盘、JVM、multipart、并发或浏览器，峰值不是进程RSS；它只说明流式校验无需一次堆内复制10 MiB，不能证明上传耗时、应用内存或100 MiB请求安全，也不足以把10/100 MiB确认为产品限额。真实实现后必须按固定样例对近上限、超上限和总请求边界测量端到端耗时、JVM峰值与原字节哈希，再决定是否沿用工程初值。

- multipart整体结构、未知字段、文件数量、数据集及会话来源检查先于任何业务提交。请求解析完成后再逐项处理；总请求超限返回413 `RESOURCE_LIMIT`，没有任何新增文件或元数据副作用。
- 单份超过10 MiB、非法文件名、媒体或编码错误按200的对应 `UploadItem.outcome=failed` 返回，保持索引对应，`file=null`、完整 `Error` 和空 `indexTaskIds`；其他成功项不回滚。不能部分成功后用整体413丢弃成功项反馈。
- 容器的单份解析限制至少允许总请求限额，业务流式检查10 MiB，不将单份10 MiB设置为解析器整请求失败门槛。临时 multipart 数据放有归属的受控目录并在成功/失败后关闭清理，不在堆内一次读入100 MiB。
- 纯文本零字节合法；严格UTF-8校验，允许UTF-8 BOM，拒绝非法字节序列及NUL二进制内容，返回逐项 `UNSUPPORTED_FILE`。不偷偷以替换字符解码成功。媒体需综合声明、扩展名和实际内容验证，不只信任客户端扩展名。
- 上传副本、哈希、字节大小按原始字节保存和计算，预览/下载不改换行、不删BOM、不统一编码。前端显示层可按UTF-8去除显示BOM，不能回写副本。
- 文件名遵循契约长度与正则，拒绝斜杠、反斜杠、控制字符、点及双点，完整展示名称不做NFC重写或首尾修剪；比较键为NFC后 `Locale.ROOT` 小写。原始失败名称按契约最多4096码点安全文本回显。

非UTF-8纯文本是否需要兼容其他编码不由原规格自动推出；本提案将严格UTF-8作为可检验技术基线。未来若用户需要其他编码，保留原字节并显式识别，不能静默猜测。

## 最小后端结构与持久化

沿用 `datasets` 领域公开接口，文件实现与数据集聚合计数在同一领域协调；共享磁盘和SQLite基础设施放 `infrastructure`，其他领域不直接访问 `datasets.data`。

schema2升级到schema3先执行既有SQLite一致性备份，校验成功后事务创建集中 `files` 与 `file_versions` 表并更新版本；失败停止启动和写入，保留旧库与备份。不用“存在则建表”绕过升级协议。

`files` 保存稳定文件标识、所属数据集、当前展示名和比较键、最新版本标识、首次上传人及时间、最近上传时间、元数据更新时间；`file_versions` 保存稳定版本标识、原上传名、类型、媒体、字节大小、原字节SHA-256、该次上传人和时间、受控相对副本路径及可用状态。传输对象严格按现有 `File` 和 `FileVersion` 输出，不泄漏内部路径。

先在本次上传专属临时目录写入、计算哈希并验证，成功后放入由后端UUID生成的独立目标，最终用串行短事务提交元数据与最新指针。磁盘写入不长期占数据库事务，提交时再次校验文件名和旧版本，避免并发穿透。提交失败只清理本次归属的新副本，不覆盖或删除旧副本；崩溃残留可按归属重新检查清理，不能扫除其他请求数据。

没有知识库关联和索引实现时 `indexTaskIds=[]`，不伪造任务或取消动作；后续索引处理由已确认提交顺序衔接。列表按稳定上传时间与标识倒序分页，数据库恢复或重启后通过实际HTTP读取验证持久化；数据集 `fileCount` 和 `totalBytes` 按最新有效文件统计，不能继续写死零。

原文读取固定版本快照并打开文件后保持读取资格，返回原格式 `text/plain` 字节，安全编码 `Content-Disposition`，预览为 `inline`、下载为 `attachment`，设置 `nosniff`、`no-store`；预览另至少 `sandbox; default-src 'none'`。忽略Range可返回完整200，不能声称支持206。动态文件名不能直接拼响应头，下载不允许客户端指定服务器路径。

## 先失败后实现的验证顺序

已读取 `mattpocock-skills:tdd` 及其测试、替身说明。沿用已批准的公共边界：提供方真实HTTP，消费方实际Axios请求/响应消费，真实浏览器界面。无需重新询问测试边界；只在系统边界注入固定时钟、系统用户名读取失败或磁盘故障，不模拟内部服务类。

每次只增加一个可观察行为测试，先运行确认因缺少行为失败，再实现使其通过；不先写整批假想测试，不靠查询数据库代替API业务结果。顺序建议如下：

1. 实际multipart纯文本上传后，经列表和元数据取回，固定已知SHA-256及字节大小，预览/下载逐字节一致；测试中含中文、BOM、换行与HTML样式文本，浏览器只安全显示。
2. 空文件、Unicode文件名、非法名称/路径/编码和未知字段、字段缺失，失败无文件副作用；按大小界限分别验证整体413与逐项失败。
3. 系统上传人正常及读取失败为空、两种可空分支、UTC时间、UUID、所有结构必填/封闭对象与计数更新；不把真实系统用户名写到报告。
4. 缺失或失效会话、伪造来源、缺少或错误CSRF、非法分页/标识、404、显式副本不可用410、真实存储500；正文和令牌不入日志或报告。
5. 应用重启后通过HTTP重新读取元数据和原字节；升级备份、备份失败、事务迁移失败及磁盘失败保护旧数据，验证不跨领域访问数据层。
6. 共享操作范围确定后，再按获派发顺序验证批量索引对应、同批冲突、未变跳过、同名变化覆盖、不同名同内容、并发与失败旧版可读、Markdown/PDF规则；未实现部分如实留在原始分母。

证据继续绑定实际实现快照与契约摘要，提供方单出口汇总并对约束标识去重，不手改JSON。前后端双80%覆盖、Spotless、SpotBugs、ArchUnit、根 `mvn verify`、真实浏览器与三宽度截图均需新证据和新签认。
